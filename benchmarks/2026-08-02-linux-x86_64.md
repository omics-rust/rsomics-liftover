# Linux x86_64 BED release gate — 2026-08-02

## Verdict

Commit `db576170a48b3b5762fd128890303298c6b2fa3e` passes the BED release
performance gate. All measured mapped and rejected outputs are byte-identical
to the official UCSC `liftOver` executable. The five-run deterministic
distribution is 39.7 times faster by median wall time and uses 4.7 times less
peak resident memory. The real `hg38ToHg19` workload is 3.8 times faster and
uses 2.6 times less peak resident memory.

## Commands

The deterministic fixture was generated with:

```text
python3 benches/generate.py --chain input.chain --bed input.bed \
  --blocks 20000 --records 100000
```

The timed commands were:

```text
taskset -c 22 rsomics-liftover bed input.bed input.chain ours.bed ours.unmapped
taskset -c 22 liftOver input.bed input.chain ucsc.bed ucsc.unmapped
```

The stress suite used the same commands, adding `--multiple` to rsomics and
`-multiple` to UCSC for the dense multiple-mapping workload. Every timed pair
was followed by `cmp` for both outputs and SHA-256 recording.

## Parse and index accounting

Thirty warm-cache, interleaved runs used the 200,000-block single-chain
fixture. `chain validate`, which parses and reports the chain without building
the map index, had a 0.03-second median. Running `bed` on an empty input, which
adds the source-chain index and a durable two-output transaction, had a
0.08-second median. The roughly 0.05-second difference is an upper bound on
index construction because it includes two file synchronizations and a
directory synchronization; CPU time remained approximately 0.02 seconds in
both paths. Mapping throughput is therefore reported separately above, and no
sub-resolution index-only claim is made.
